# music-utils monorepo

TypeScript toolkit for managing a personal FLAC/MP3 music collection. Three packages, published independently to npm via OIDC Trusted Publisher:

| Package | Description |
|---------|-------------|
| [`@hansogj/music-utils`](./packages/music-utils) | Top-level CLI suite: CD ripping via `cdparanoia`, tag reading/writing, Discogs metadata lookup, cover art fetching, folder-structure normalization. Depends on the other two. |
| [`@hansogj/discogs-item-lookup`](./packages/discogs-item-lookup) | Standalone client + CLI for fetching release metadata from the Discogs API. |
| [`@hansogj/discogs-cover`](./packages/discogs-cover) | Standalone client + CLI for fetching and downloading album cover art from Discogs. |

The typical end-user only installs `@hansogj/music-utils` (which brings the other two along transitively). The lower-level packages are useful on their own if you just need Discogs lookups or covers without the ripping/tagging pipeline.

## `scripts/audit` — music-audit CLI

Private, unpublished tool for auditing and interactively repairing a local music library. See [`scripts/audit/README.md`](./scripts/audit/README.md) for full usage, flags, and repair mode docs.

```bash
sudo bash scripts/install-bins.sh   # install music-audit binary system-wide
```

## Development

**Package manager**: pnpm. Node 26.x via nvm; run nvm use to switch to the version in .nvmrc. pnpm is not installed by hand: nvm installs it automatically into each Node version from ~/.nvm/default-packages (maintained in the dotfiles repo). If pnpm is missing after nvm use, that Node version was installed before the list existed; run npm i -g pnpm once, or reinstall that version with nvm install. Don't use corepack, and don't install tooling with pnpm add -g.

```bash
pnpm install
pnpm --filter @hansogj/music-utils run test
pnpm --filter @hansogj/music-utils run precommit
```

Per-package scripts live in each `packages/*/package.json`; the workspace root has a monorepo-wide `precommit` that runs each package's `precommit` sequentially (via `pnpm -r`).

### Bash completion

`music-utils completion bash` prints completion for `music-utils` / `mu` (subcommands, flags, directory/file arguments). bash-completion loads a file named after the command, so install it under both names:

```bash
mkdir -p ~/.local/share/bash-completion/completions
music-utils completion bash > ~/.local/share/bash-completion/completions/music-utils
ln -sf music-utils ~/.local/share/bash-completion/completions/mu
```

For the standalone `music-audit` command (from the repo root):

```bash
pnpm --dir scripts/audit run --silent completion > ~/.local/share/bash-completion/completions/music-audit
```

Or source either for the current session only: `source <(music-utils completion bash)`.

### Releases

All published packages (`@hansogj/music-utils`, `@hansogj/discogs-item-lookup`, `@hansogj/discogs-cover`) are versioned with [Changesets](https://github.com/changesets/changesets). `scripts/audit` (`@hansogj/music-audit`) is private and never published.

1. With each change, add a changeset: `pnpm changeset` (pick packages, bump type, summary), or write `.changeset/<name>.md` by hand. Commit it with the change.
2. To cut a release, on a branch: `pnpm version-packages` — bumps versions, writes each package's `CHANGELOG.md`, consumes the changesets and refreshes the lockfile. Commit, open a PR, merge.
3. From an up-to-date `main`: `npm login` if needed, then `pnpm release` (add `--otp=<code>` when npm asks for 2FA). It checks the npm login, builds, publishes every package whose version isn't on npm yet and creates `@hansogj/<pkg>@<version>` tags.
4. Push the new tags: `git push origin --tags` (changesets creates lightweight tags, which `--follow-tags` skips).

The root `CHANGELOG.md` is the history up to music-utils 2.1.0 (generated by changelogen); newer entries are in each package's own `CHANGELOG.md`.
